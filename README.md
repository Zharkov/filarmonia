# Сайт Смоленской областной филармонии

Самописный сайт на Python: Flask + SQLAlchemy + собственная админка. Без конструкторов
и сторонних CMS. База — SQLite для разработки, PostgreSQL для боевого сервера.

---

## Быстрый запуск

Всё делается одним файлом `app.py`.

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python app.py seed --reset      # создаёт базу, структуру разделов и демо-контент
python app.py                   # http://127.0.0.1:8000
```

На Windows то же самое:

```powershell
python -m venv venv; venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py seed --reset
python app.py
```

Админка: <http://127.0.0.1:8000/admin> — логин `admin`, пароль `filarmonia2026`.
**Смените пароль до выхода в интернет** (Сотрудники → выбрать себя → новый пароль).

### Команды

| Команда | Что делает |
|---|---|
| `python app.py` | запускает сайт на 8000 порту в режиме разработки |
| `python app.py --port 5000` | другой порт; есть также `--host` и `--no-debug` |
| `python app.py seed` | создаёт таблицы и наполняет, не трогая уже введённое |
| `python app.py seed --reset` | очищает базу и наполняет заново |
| `python app.py test` | прогоняет проверку основных сценариев админки |
| `python app.py --help` | справка по командам |

Демо-афиши, фотографии и ролик создаёт модуль `filarmonia/demo.py` — он вызывается
командой `seed`. На боевом сайте их заменяют настоящие файлы, загруженные через админку.

Шрифты для демо-картинок берутся из системы (DejaVu на Linux, Georgia и Segoe UI
на Windows). Для демо-роликов нужен `ffmpeg`: либо системный, либо `pip install
imageio-ffmpeg`. Если его нет, наполнение пройдёт без ошибок — просто без видео:
на главной останется кадр-заставка.

отключение изображений — настройка запоминается в браузере), `sitemap.xml`, `robots.txt`,
адаптивная вёрстка, работа с клавиатуры, учёт `prefers-reduced-motion`.

### Админка (`/admin`)

Афиша · Новости · Коллективы · Галерея · Страницы · Документы · Обращения граждан ·
Меню · Баннеры · Площадки и жанры · Настройки · Сотрудники.

Ключевое по вашему ТЗ:

- **Льготы и Пушкинская карта** — два отдельных блока в карточке события. У каждого
  своя галочка «показывать» и свой текст: для одного концерта показываем, для другого
  убираем, ничего не удаляя из системы. Если текст о Пушкинской карте пуст, подставляется
  общий из раздела «Настройки».
- **Всплывающие баннеры на афише** — сколько угодно меток поверх афиши. Задаются
  надпись, подсказка при наведении, угол размещения (4 варианта), цвет (4 варианта)
  и необязательная ссылка. На телефоне подсказка открывается касанием.
- **Галерея фото и видео** — одинаковый блок у события, коллектива, новости и альбома.
  Фотографии грузятся пачкой. Видео — либо файлом `.mp4`/`.webm`, либо ссылкой на
  **VK Видео, RuTube, Дзен, YouTube**: ссылка автоматически превращается в проигрыватель
  (`filarmonia/utils.py`, функция `video_embed`). Это под задачу «артисты присылают ролики и фото».

### Структура разделов

Заполнена по требованиям к сайтам учреждений культуры: об учреждении (общие сведения,
об учредителе, структура, история, материально-техническая база, контакты и схема проезда),
услуги, годовые отчёты, независимая оценка качества, план ФХД, НПА, противодействие
коррупции, интернет-приёмная, распорядок приёма посетителей, политика конфиденциальности,
обработка персональных данных, ссылки на gosuslugi.ru и bus.gov.ru.

Меню полностью редактируемое: пункт ведёт либо на страницу сайта, либо на любой адрес,
вложенность — два уровня.

### Модели базы

`User` · `Setting` · `Page` · `MenuItem` · `Venue` · `Category` · `Event` · `EventBadge` ·
`MediaItem` · `Album` · `Collective` · `News` · `Document` · `Banner` · `Appeal`.

`MediaItem` — общая таблица фото и видео: привязывается к событию, коллективу, новости
или альбому. `EventBadge` — всплывающие баннеры на афише события.

## Развёртывание на боевом сервере

Хостинг должен быть российским, домен и хостинг оформлены на учреждение — это
требование к сайтам учреждений культуры.

Чтобы просто показать сайт заказчику по временному адресу, есть готовая
конфигурация для render.com: [DEPLOY-RENDER.md](DEPLOY-RENDER.md). Это площадка
для демонстрации, не для эксплуатации.

### 1. Окружение

```bash
sudo apt install python3-venv nginx postgresql
adduser --system --group filarmonia
cd /var/www/filarmonia && python3 -m venv venv
venv/bin/pip install -r requirements.txt "psycopg[binary]"
```

### 2. Переменные окружения (`/etc/filarmonia.env`)

```
SECRET_KEY=<длинная случайная строка>
DATABASE_URL=postgresql+psycopg://filarmonia:пароль@localhost/filarmonia
UPLOAD_FOLDER=/var/www/filarmonia/uploads
SESSION_COOKIE_SECURE=1
```

Ключ можно получить так: `python -c "import secrets; print(secrets.token_hex(32))"`.

### 3. Инициализация базы

```bash
venv/bin/python app.py seed   # создаст таблицы, структуру разделов и учётную запись admin
```

Демо-контент из `filarmonia/seed.py` перед запуском в эксплуатацию можно не создавать:
закомментируйте блоки с событиями, новостями и альбомами — обязательная структура
разделов создастся в любом случае.

### 4. gunicorn (`/etc/systemd/system/filarmonia.service`)

```ini
[Unit]
Description=Сайт филармонии
After=network.target

[Service]
User=filarmonia
WorkingDirectory=/var/www/filarmonia
EnvironmentFile=/etc/filarmonia.env
ExecStart=/var/www/filarmonia/venv/bin/gunicorn -w 3 -b 127.0.0.1:8001 "app:app"
Restart=always

[Install]
WantedBy=multi-user.target
```

### 5. nginx

```nginx
server {
    listen 443 ssl http2;
    server_name smolensk-filarmonia.ru;

    client_max_body_size 64m;          # загрузка видео из админки

    location /static/ { alias /var/www/filarmonia/filarmonia/static/; expires 30d; }
    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 6. Резервные копии

```bash
pg_dump filarmonia > /backup/filarmonia-$(date +%F).sql
tar czf /backup/uploads-$(date +%F).tar.gz /var/www/filarmonia/uploads
```

## Что нужно доделать перед публикацией

1. **Шрифты.** Сейчас Cormorant Garamond и Golos Text подключены с Google Fonts
   (`filarmonia/templates/public/base.html`). Для российского хостинга их лучше положить
   локально: скачать `.woff2`, сложить в `filarmonia/static/fonts/`, заменить `<link>` на
   правило `@font-face` в `site.css`. Запасные шрифты уже прописаны, без интернета
   сайт остаётся читаемым.
2. **Билетная система.** Сейчас у события есть поле «Ссылка на покупку билета».
   Если у филармонии есть оператор (Ticketland, Радарио, Яндекс Афиша, собственная
   касса) — под него делается виджет или обмен данными вместо простой ссылки.
   Скажите, какой оператор, и я встрою.
3. **Перенос контента** со старого сайта: афиша, новости, документы, фотографии.
   Старый сайт на Drupal 7 — данные можно выгрузить из его базы и залить скриптом,
   это отдельная задача на пару часов.
4. **Юридические тексты.** Политика конфиденциальности, согласие на обработку
   персональных данных, уведомление Роскомнадзора — шаблоны страниц созданы,
   тексты нужно согласовать с юристом учреждения.
5. **Счётчики.** Яндекс.Метрика и, если требуется, виджет «Госуслуги. Решаем вместе» —
   код вставляется в конец `base.html`.
6. **Почта.** Сейчас обращения граждан сохраняются в базу и видны в админке.
   Если нужно дублировать письмом ответственному сотруднику — добавлю отправку
   через SMTP учреждения.

## Проверка

```bash
python app.py test
```

Проверяет вход в админку, создание события, загрузку афиши, всплывающие баннеры,
загрузку фотографий пачкой, распознавание ссылки на видео, отклонение недопустимых
файлов, включение и выключение блока льгот, удаление события, закрытость админки
от гостей. Работает на временной базе и не трогает рабочие данные.
