# Тестовый показ сайта на render.com

Пошаговая инструкция, чтобы получить работающий адрес вида
`https://filarmonia.onrender.com` и показать сайт заказчику.

> **Это не боевая площадка.** По требованиям к сайтам учреждений культуры хостинг
> и домен должны быть российскими и оформлены на учреждение. Render подходит только
> для демонстрации и проверки. Боевая установка (nginx + PostgreSQL + systemd)
> описана в [README.md](README.md).

---

## Что уже готово в репозитории

| Файл | Зачем |
|---|---|
| `render.yaml` | описание сервиса: Render прочитает его сам и всё настроит |
| `.python-version` | Python 3.11.9 — та же версия, что локально |
| `requirements.txt` | зависимости; `gunicorn` уже в списке |

Демо-контент создаётся **на этапе сборки**: `python app.py seed` рисует афиши
и фотографии и наполняет базу. Поэтому сайт открывается сразу наполненным,
без ручных команд после деплоя.

---

## 1. Репозиторий на GitHub

Локальный репозиторий уже создан и закоммичен. Осталось создать пустой репозиторий
на GitHub (**без** README и .gitignore) и отправить туда код:

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/filarmonia.git
git push -u origin main
```

Репозиторий может быть приватным — Render запросит доступ при подключении.

## 2. Создать сервис на Render

1. Зайти на <https://dashboard.render.com> (регистрация через GitHub — проще всего).
2. **New → Blueprint**.
3. Выбрать репозиторий `filarmonia`. Render найдёт `render.yaml` и покажет
   один web-сервис `filarmonia` на плане Free.
4. Render спросит значение **ADMIN_PASSWORD** — придумайте пароль администратора
   и запишите его. Он попадёт в базу при сборке; пароля `filarmonia2026`
   из репозитория на этом сайте не будет.
5. **Apply** — начнётся сборка.

Первая сборка занимает примерно 5–8 минут: устанавливаются зависимости и рисуются
64 демо-картинки и два видеоролика. Прогресс виден в логах, в конце должно быть
`База наполнена.`

## 3. Проверить

| Адрес | Что там |
|---|---|
| `https<имя>.onrender.com/` | главная с афишей |
| `/admin` | админка, логин `admin`, пароль из шага 2.4 |
| `/robots.txt` | `Disallow: /` — тестовый адрес закрыт от поисковиков |

## Что нужно знать про план Free

* **Сайт засыпает** после 15 минут без запросов. Первый запрос после сна
  открывается 30–60 секунд — это нормально, дальше быстро. Перед показом
  заказчику откройте сайт заранее, чтобы он «проснулся».
* **Данные сбрасываются.** Диск у free-сервиса временный: при каждом деплое
  и после пробуждения база и загруженные файлы возвращаются к демо-состоянию.
  Всё, что внесено через админку, теряется. Для показа это удобно — сайт всегда
  в нормальном виде; для наполнения настоящим контентом — нет.
* **512 МБ памяти, 0.1 CPU** — для показа хватает с запасом.

## Если данные должны сохраняться

Понадобится платный план (Starter, $7/мес) и постоянный диск. В `render.yaml`
заменить `plan: free` на `plan: starter`, убрать `python app.py seed` из
`buildCommand` и добавить диск:

```yaml
    disk:
      name: data
      mountPath: /var/data
      sizeGB: 1
    envVars:
      - key: DATABASE_URL
        value: sqlite:////var/data/filarmonia.db
      - key: UPLOAD_FOLDER
        value: /var/data/uploads
```

После первого деплоя базу создают один раз вручную: **Shell** в панели Render →
`python app.py seed`.

> Отдельная бесплатная база PostgreSQL на Render эту задачу не решает: строки
> сохранятся, а загруженные файлы всё равно пропадут, и вместо фотографий
> останутся битые ссылки.

## Настройки, которые включены только для Render

Задаются переменными окружения из `render.yaml`, локальная работа не меняется:

| Переменная | Значение | Что делает |
|---|---|---|
| `SECRET_KEY` | генерирует Render | подпись сессий |
| `SESSION_COOKIE_SECURE` | `1` | cookie только по HTTPS |
| `TRUST_PROXY` | `1` | брать протокол и адрес клиента из `X-Forwarded-*`, иначе в `sitemap.xml` попадёт `http://` |
| `SITE_NOINDEX` | `1` | `noindex` в шаблоне и `Disallow: /` в `robots.txt` |
| `ADMIN_PASSWORD` | задаёте вы | пароль администратора при создании базы |

На боевом сервере `SITE_NOINDEX` не ставится (сайт должен индексироваться),
остальные — по README.
